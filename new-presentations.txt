Finding and Crushing Bugs and More with JFR

Some of the most difficult issues a developer will face are slow developing resources leaks, or errors that occur at infrequent intervals. When these happen, finding the root cause can be difficult, and a frequent recourse by developers is to add a lot of logging statements around suspected problem sites. What if I told you there was a better option, and that option already existed right in the JVM you are already running? JDK Flight Recorder, as its namesake suggests, is a low-overhead profiling and diagnostic tool that[s been built directly into the JDK since JDK 7. In this presentation we are going to look at how developers can leverage JFR's powerful API and reporting tools for tracking down those difficult bugs as well as how JFR can be incorporated into the development process.

Agentic Coding Tools Are Powerful. The Secret Is in the Harness.

Agentic coding tools like Codex, Claude Code, Cursor, and others are incredibly powerful. With just a few prompts, users are able to "vibe code" an entire application. However, the experience for many users is that while these applications might work on a surface level, they fail under closer scrutiny. Requirements the agent said were fulfilled weren't, processes the agent claimed were completed aren't, and users are left with a bug-filled, error-prone application with a dense, confusing codebase they don't understand.

Close enough might be good enough for horseshoes and hand grenades, but not for applications operating in the real world, where a business risks financial and reputational losses when mistakes occur.

The good news is that there is a way forward! We can take advantage of agentic coding tools to build applications, and have them build high-quality applications. The secret is all in the harness.

An agentic harness is user-supplied infrastructure that provides agentic coding tools with the important context, guardrails, tools, and memory needed to accomplish the complex tasks involved in modern software development.

In this presentation, using examples, we will cover what an agentic harness is, how to build one, and the key principles and philosophies attendees should consider when building their own agentic harness to assist them in their work.

If you have been struggling with the output from AI-generated code at work, then this is the presentation for you!

Autopilot: Building the Ultimate Ops Engineer with JFR and AI

JDK Flight Recorder (JFR) is an observability and diagnostic framework built directly into the JDK. It can provide a rich and detailed view into how your application and the JVM are behaving at runtime. It is able to do this while maintaining a sub-1% impact on application throughput, allowing it to be always on in production.

While JFR is an incredibly powerful tool, its utilization is rather low, and the amount of information it provides can feel overwhelming. JFR can be always on, but the engineers needed to analyze its recordings can't be. And if an issue happens at 2:00 a.m., it might mean waiting hours before a human engineer can review the recording and offer a solution.

In this presentation, we will look at how JFR can be combined with agentic AI to build the ultimate Ops engineer: an engineer that can review JFR recordings and propose improvements to an application; an engineer that is always available, day and night, and able to respond in real time as issues occur.

If you have been looking for novel opportunities to incorporate AI into your organization or improve the performance of your applications in production, this is a presentation you don't want to miss.

Structured Concurrency: A New Age for Writing Concurrent Code in Java

Horizontal scalability and handling concurrently executing tasks have historically been difficult challenges in Java. Horizontal scalability was largely addressed with the introduction of Virtual Threads in JDK 21; however, properly handling concurrently executing tasks remained a TODO. With Structured Concurrency at last arriving as a final feature in JDK 28, properly handling concurrent tasks is finally moving into the "done" category.

The Structured Concurrency API allows developers to treat a group of related tasks executing in separate threads as a single unit of work. In this presentation, we will cover the essential elements of using StructuredTaskScope-the central feature of the Structured Concurrency API-the use cases for "joining" tasks already provided by the JDK, how developers can extend and customize the Structured Concurrency API to fit their specific needs, and the operational benefits of using structured concurrency over other options for writing concurrent code.

If you have been struggling with handling concurrent code in your organization or have been following the development of the Structured Concurrency API and are excited to finally see the "final" version of it, this is the presentation for you.
